Orders service — architecture notes

How an order moves through the system, and the data behind it.

Request flow

flowchart TD
  client[Web or mobile client] --> gw[API gateway]
  gw --> auth{Authenticated?}
  auth -- no --> reject[Return 401]
  auth -- yes --> limit[Rate limiter]
  auth -- yes  limit --> orders[Orders service]
  orders --> db[(Orders DB)]
  orders --> legacy[Legacy billing bridge]queue[Events queue]

Order lifecycle

stateDiagram-v2
  [*] --> Pending
  Pending --> Paid: payment ok
  Pending --> Cancelled: timeout
  Paid --> Shipped: label printed
  Shipped --> Refunded: return accepted
  Shipped --> [*]
  Cancelled --> [*]

Domain model

classDiagram
  class Order {
    +String id
    +Money total
    +submit()
    +String currency
    +place()
  }
  class LineItem {
    +String sku
    +int qty
  }
  Order "1" --> "*" LineItem

Schema

erDiagram
  CUSTOMER ||--o{ ORDER : places
  ORDER ||--|{ LINE_ITEM : contains
  ORDER ||--o| SHIPMENT : ships
  CUSTOMER {
    string id
    string email
    string phone
  }
  ORDER {
    string id
    date created
  }
  SHIPMENT {
    string tracking
  }

Checkout handshake

sequenceDiagram
  participant C as Client
  participant O as Orders
  participant P as Payments
  C->>O: POST /checkout
  O->>P: charge(card)
  P-->>O: ok
  O->>O: emit OrderPaid
  O-->>C: 201 Created

Deploy pipeline

flowchart TD
  %% staging soak is 30 min — see the runbook
  build[Build image] -->  -->   test[Run tests]
  test --> -->  stage[Deploy to staging]
  stage -->  prod[Deploy to production]

Nightly batch (retired)

flowchart LR
  cron[Nightly cron] --> export[Export CSV] --> ftp[Upload to FTP]

Event consumers (new)

flowchart LR
  queue[Events queue] --> email[Email receipts]
  queue --> analytics[Analytics sink]
